The recurring import workflow

Every time you download a new XLSX, start a new import. Overlapping dates are expected: Ruby rechecks MoneyWiz and the persistent ledger to identify existing records.

1

Prepare & compare

Run import with your XLSX. A fresh backup, plan, CSV, and this static review page are saved in a separate folder for this run.

2

Review & save decisions

Filter New and Need review. Match, mark new, skip, or defer records one by one, or tick several rows (across pages) and use the bulk bar. Pick a category per record or in bulk; answer whether it should always apply to that merchant. Use Save decisions before leaving; a browser draft is not an exported file.

3

Apply

Run apply on the plan. It reads decisions.json from the run folder, rechecks everything against a fresh backup, then creates the reviewed New entries one by one and verifies each save.

Every command

CommandWhat it does
moneywiz_import.rb import FILE.xlsx […]Start a new dated run, compare with a fresh database backup and ledger, save JSON/CSV/HTML, and open review. No app writes.
moneywiz_import.rb plan FILE.xlsx […]Generate the same outputs at private/plan.json by default. Does not open a browser unless --open is supplied.

Options

  • --config PATH: use another config file; default is config.json beside the script.
  • --snapshot PATH: use an existing backup for import, plan, resolve, or accounts. Apply always creates fresh backups.
  • --decisions PATH: load decisions during import, plan, resolve, or apply. Apply reads decisions.json beside the plan when this flag is absent. The file replaces the plan’s previous decision set, so exports include all current decisions.
  • --out PATH.json: choose output for import, plan, or resolve. CSV and HTML use the same filename stem.
  • --open / --no-open: control whether the review page opens. Import and review open it by default.
  • -h / --help: show help.

Resume, repeat, and recover

  • Resume a review: reopen the same HTML file or run review with its plan. Drafts restore for that exact plan where localStorage is available. Use Load decisions for a saved file; it replaces the current draft.
  • Next bank export: run import with the new XLSX. Keep private/ledger.json. Already saved transactions are recognized automatically; do not reuse an old decisions file with a different statement.
  • Overlapping exports: pass multiple XLSX paths to import. The same source identities are deduplicated across files.
  • Partial import: defer uncertain rows, save decisions, and apply the rest. Deferral applies to this plan, while Skip is remembered after applying.
  • Interrupted save: start a fresh import from the same XLSX. A delayed save can be recognized by its marker. Unconfirmed dispatches remain locked; do not delete the ledger or retry URLs manually.
  • Combined entries: compare the displayed candidates and amounts. If one app record covers several bank rows, skip the covered rows after confirming them. One-to-one Match cannot assign one app record to several rows.
  • Transfers, FX, cash movements: proposed as New like purchases, but created uncategorized and titled with the bank row type (Incoming Transfer, Outgoing Transfer, FX). The counterparty is shown in the record panel. Skip rows already covered, or defer them; convert the created records into transfers in MoneyWiz afterwards.
  • Account changes: run accounts, update config.json, then generate a fresh import. Import details shows the mappings used by this plan.

What can a static page do?

The page works from a file on disk, with no server or external assets. It can read files you choose, review all plan records, cache decisions, and save JSON using a file picker where supported or a download otherwise. It cannot run Ruby, inspect MoneyWiz’s database, or reliably verify URL saves. Those steps remain terminal commands.

Drafts are written after each change. Use Save decisions before closing: file writes cannot be guaranteed during tab shutdown, and localStorage on file URLs varies by browser. See localStorage behavior and browser exit limitations.
